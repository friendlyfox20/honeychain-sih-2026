============================================================
1. HONEYCHAIN PRODUCT PURPOSE
============================================================

HoneyChain is a:

- honey supply-chain traceability platform
- evidence and reconciliation system
- batch genealogy system
- honey intelligence/ML system
- anomaly detection system
- QR-based consumer verification system
- blockchain integrity layer
- voice query system
- admin analytics and monitoring system

The core physical flow is:

Hive
  ↓
Harvest
  ↓
Collection
  ↓
Processing
  ↓
Laboratory
  ↓
Packaging
  ↓
Distribution/Retail
  ↓
Consumer

The frontend should make this journey understandable.

The central idea is:

TRACEABILITY + EVIDENCE + INTELLIGENCE + INTEGRITY

not simply:

"Blockchain + QR + AI"

============================================================
2. VERY IMPORTANT PRODUCT PRINCIPLES
============================================================

The frontend must respect these principles:

1. Do not blindly trust self-reported data.

2. Do not claim that blockchain creates truth.

3. Do not claim HoneyChain replaces laboratory/regulatory testing.

4. Do not make the interface unnecessarily complicated for rural/non-technical users.

5. IoT/sensor ingestion is NOT part of the current implementation.

6. Do not use AI where deterministic rules are more appropriate.

7. For consumers, show evidence and traceability rather than overwhelming them with technical blockchain details.

8. Do not store or display unnecessary information from blockchain.

9. Do not imply that the system guarantees physical authenticity of honey.

10. Every frontend feature should correspond to an actual backend capability.

============================================================
12. RECONCILIATION
============================================================

Endpoint:

POST /api/v1/batches/{batch_id}/reconcile

Reconciliation checks quantity flow.

Core principle:

Output quantity should not exceed input quantity.

For example:

Harvest:
50 kg

Processing:
48 kg

Bottling:
46 kg

Dispatch:
45 kg

This is reasonable.

But:

Harvest:
50 kg

Processing:
62 kg

is a quantity violation.

The backend uses deterministic rules as an authoritative layer.

The frontend should clearly show:

NORMAL

or

ANOMALY / VIOLATION

Do not override the backend result.

Do not create fake discrepancy calculations if the backend already provides them.

- hive humidity
- wind speed
